# FINCA·HaTA CX 운영 대시보드

VOC · 리뷰 · 게시판 · 주문 · CS 데일리 · 예약배송 · 회의록 · 팀 업무를 한곳에서 관리하고, 주간·월간 보고를 자동으로 만드는 사내 대시보드입니다.

- **접속 주소**: https://finca-hata-cx.netlify.app
- **로그인**: 공용 직원 계정 (계정 정보는 CX팀장에게 받기 · Supabase Authentication에서 관리 · 외부 가입은 막혀 있음)
- 화면이 바뀌지 않으면 **Ctrl + Shift + R** (강제 새로고침). 화면 비율이 이상하면 **Ctrl + 0**.

## 매일 하는 일 (순서)

1. **📤 데이터 업로드** — 전일 **주문 · 리뷰 · 게시판** 파일을 올립니다. 여러 파일을 한 번에 골라도 종류와 **핀카·하타를 알아서 구분**하고(브랜드 칸 또는 파일 이름, 둘 다 없을 때만 브랜드 선택 칸이 나옴), 이미 올린 건은 다시 올려도 중복 저장되지 않습니다.
2. **🗓️ CS 데일리** — 보고일을 고르고 **📥 업로드 데이터로 채우기** → 주문·출고전 취소·리뷰·게시판이 자동으로 채워집니다. **반품·교환 · 해피톡 · 전화**는 직접 입력하고 **💾 저장**.
3. **📸 데일리 리포트** (CS 데일리 화면 위 버튼) — **📝 제목 글 복사** → 슬랙에 붙여넣기 → **📋 이미지 복사** → 슬랙에서 Ctrl+V.
4. **📦 예약배송 관리** — 오클릭 **미출고 파일**을 올립니다(하루 여러 번 가능). 파일에서 빠진 주문은 자동으로 출고완. **📞 안내 대상**에서 지연 고객 안내 후 **안내 완료** 기록.
5. **🏠 메인 요약**의 **🔔 오늘 챙길 것** 확인 — 처리 대기 VOC · 예약배송 안내 필요 · 업무 마감 임박 · 리뷰 체크필요.

**가끔 하는 일**
- **한 달에 한 번 백업**: **📤 데이터 업로드 → 📦 전체 백업 받기** → 받은 엑셀은 회사 드라이브 비공개 폴더에 보관 (30일 지나면 메인에 알림)
- 신상품이 나오면: **📤 데이터 업로드 → 🏷️ 상품 마스터 올리기**에 오클릭 카테고리 파일 그대로 (새 상품만 추가, 분류·추가분류 바뀐 상품만 수정)
- 예약상품 일정이 바뀌면: **예약배송 관리 → 🗓️ 예약상품 일정**에서 단계별 입력 (① 처음 일정 → ② 1차로 밀림 → ③ 또 밀림 → 입고 완료)
- 회의 날: **CX 미팅 로그 → + 새 회의록 → 📊 주간 CX 리포트 넣기**

## 알아두면 좋은 기준

**CS 데일리 · 보고서**
- **데이터는 전일 기준**: 보고일 9/22 = 9/21 데이터. 월요일 보고일에는 금~일 3일치를 합칩니다.
- **한 주 = 월~일** (데이터 날짜 기준). 매월 첫 화요일 보고일이 그달 1주차 시작. 예) 9월 1주차 = 8/31~9/6.
- **📸 데일리 리포트** (CS 데일리): 브랜드별 숫자(0인 판매처도 표시, 해피톡은 브랜드별·하타는 전화 없음) + **📌 액션 포인트**(재입고 최근 7일 3건 이상 → 리오더 검토, 부정 리뷰·과실 VOC 상품 → 검수·개선) + **게시판 문의 유형·재입고 문의 상품(오늘·7일)** + **리뷰 긍정/부정 비중·많이 나온 말·부정 리뷰 발췌** + 그날 VOC(사진 = VOC에 첨부한 첫 사진).
- CS 데일리 해피톡 **총 상담**·전화 **총 인입**은 세부 칸 합계로 자동. VOC 목록에 **문의 채널** 필터(리뷰만 보기 등).
- **업로드로 채우기**: 주문은 **오클릭 주문 파일**(CSV 그대로) 기준. 주문건 = **상품 수**(29CM·아임웹 모두, 세트는 1개로), **출고전 취소도 오클릭·사방넷 기준으로 자동**으로 채워집니다 (들어오기 전에 바로 취소된 주문은 주문건·취소 모두에서 빠져 판매처 화면 숫자보다 적음). 예전 손 입력 값은 따로 보관돼 있습니다. 핀카 오클릭 파일은 **아침 8시 오클릭 업로드가 끝난 뒤에** 받으세요. **하타 주문은 사방넷 파일**("주문서확인처리_CS 양식")을 올립니다 (오클릭 파일의 하타 줄은 자동으로 빠짐). 교환 재발송·시딩·샘플·B2B는 빠짐. 자사몰은 지금 아임웹(카페24도 아임웹 칸으로 합산). 2026-09-30 이전에 손으로 넣은 숫자는 따로 보관돼 있습니다.
- **과실(브랜드 과실)**: VOC 구분이 품질 · 세탁·이염 · 내구성인 건.
- **리뷰**: 부정 = 1~3점, 긍정 = 4~5점. 새로 올라온 1~3점 리뷰는 VOC로 자동 등록(상품명으로 상품 마스터를 찾아 대분류·중분류 연결).
- 메인 지표는 **지난달 같은 기간**과 비교합니다(월 중간에도 공정하게).

**예약배송**
- **구매일** = 판매처주문번호 안의 날짜(없으면 오클릭 입력일).
- 구매일이 **n차 안내 시작일보다 뒤**면 바뀐 일정을 보고 산 고객 → 그 뒤로 또 바뀐 횟수만큼만 지연. 안내 시작일 당일 주문은 * 표시(주문 시각 확인).
- 출고일이 늦어지지 않았으면 지연 아님.
- 오클릭 파일을 올릴 때마다 **파일에 없는 주문 = 출고완** (판매처 통째로 빠짐 · 줄 수 30% 미만이면 먼저 확인 · 되돌리기 가능).
- **실제 입고일이 있고 기다리는 주문이 없는 예약상품은 자동 종료**. 입고됐는데 미출고가 남으면 🟡 표시.
- 사은품 목록: 기준 관리 → 예약배송 사은품 ("코드 단품) 상품명" 형식, 앞 숫자 = 오클릭 바코드 → 저재고 계산에서 제외).
- 예약상품 일정은 **대시보드에서만** 고칩니다(구글시트를 다시 올리면 덮어써짐).

**개인정보**
- 주문·리뷰·게시판 업로드는 고객 이름·연락처·주소를 저장하지 않습니다.
- 주문 파일에서 **주문 날짜 칸에 날짜가 없는 줄(칸이 밀린 줄 등)은 저장하지 않고** "날짜 없는 N줄 제외"로 알려줍니다. 하타 상품명(영어)도 대분류가 자동으로 잡힙니다.
- VOC 사진은 올릴 때 **긴 변 2500px · JPEG로 자동으로 줄여서** 저장합니다(장당 약 0.5~1MB). 원본은 휴대폰·PC에 그대로 남습니다.
- **지난 주문(상반기 등)** 은 업로드 확인표 아래 **"주문은 월·상품별 요약으로만 저장"** 을 체크하고 올립니다. 월·판매처·상품별 주문·취소·반품·교환 개수만 저장돼 용량이 약 1/20입니다. **7월부터의 주문은 체크하지 않고** 평소처럼 올립니다 (CS 데일리 자동 채우기에 필요).
- 예약배송만 안내를 위해 **주문자 이름**을 저장합니다(연락처·주소는 저장 안 함).

|---|---|
| 리뷰 | 29CM(원본·파트너 화면) · 아임웹 · 무신사 · 기존 시트 '리뷰 low' (엑셀/CSV) |

다운로드가 안 되는 게시판은 화면에서 긁어서 **게시판 공통 양식**(브랜드·판매처·작성일·상품명·문의유형·제목·문의 내용)에 붙여넣어 올립니다 (데이터 업로드 → 📄 파일 형식 보기 · 양식 받기 → 게시판 → '직접 정리한 게시판 (공통 양식)'). 필수 칸은 **판매처·작성일**뿐 (문의 내용은 없어도 됨. 문의유형·제목으로 유형 분류, 게시판 건수·재입고 순위에 쓰임).

직접 만들어 올리는 파일은 각 업로드 화면의 **📄 양식** 버튼으로 칸 이름이 들어 있는 빈 엑셀을 받아 채우면 됩니다(데이터 업로드 → 📄 파일 형식 보기 · 양식 받기, 상품 마스터, 예약배송 파일 올리기).
처음 보는 형식은 "형식을 알 수 없어 건너뜀"으로 표시됩니다. 새 형식은 `src/upload.jsx`(리뷰·게시판)·`src/orders.jsx`(주문)·`src/preorder.jsx`(예약배송)에 추가합니다.

## 관리자용 정보

### 구성
- **화면**: `index.html` + `app.css` + `src/*.jsx` (React + 브라우저 Babel, 빌드 없음)
- **데이터**: Supabase 프로젝트 `hbudvjnqzejqbvkqfklz`. 모든 테이블은 로그인한 직원만 읽기·쓰기(RLS). 사진·첨부는 비공개 저장소(voc-photos · manual-files)
- **배포**: GitHub `main`에 올리면 Netlify가 1분 안에 자동 반영. 반영이 멈추면 Netlify **Deploys**에서 멈춘 배포 **Cancel** → 다음 배포 진행(또는 **Trigger deploy**)
- **저장소는 공개**라 고객 데이터·매출 자료·계정 비밀번호는 절대 올리지 않습니다. 시트 주소 같은 설정은 DB(code_items)에 저장합니다.
- 개발 작업 기록·규칙은 `CLAUDE.md`에 있습니다.
